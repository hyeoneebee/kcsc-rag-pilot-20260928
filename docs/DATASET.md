# 데이터셋과 전처리

## 1. 검색 대상과 질문셋은 다르다

- **검색 대상:** KCSC `2026-08-12-full` 스냅샷의 검색 가능 문서 3,520개, 절 557,027개.
- **평가 질문:** 전체 코퍼스에서 구성한 48문항. 유형별 12개이며, 철도 할당·제외 없음.
- 48문항이 전체 검색 문서를 고르게 대표한다는 뜻은 아니다. 원문에서 출발해 목적에 맞게 고른 작은 탐색 표본이다.

원천 목록 3,576건 중 정상 본문 3,520건만 검색한다. 빈 응답 53건과 요청·응답 식별자가 다른 3건은 제외했다. 전체 저장 절 557,749개 중 격리 절 722개가 검색에서 제외되어 557,027개가 된다. 수치 출처: [코퍼스 빌드 보고서](../provenance/corpus_build_report.json).

문서 계열은 EXCS, KCS, KDS, KRACS, KRCCS, KWCS, LHCS, NHCS, SMCS의 9개다. 시점별 모든 판본을 모은 변경 이력 코퍼스는 아니다.

## 2. 전처리: 원문 절을 검색 단위로 사용

1. 수집한 API 응답을 스냅샷으로 고정하고 파일 해시를 기록했다.
2. 원문 HTML은 보존하고, 검색용 텍스트 `text_search`를 별도로 만들었다.
3. 스크립트·스타일은 검색 텍스트에서 제외한다. 블록/행 경계를 줄바꿈으로, 표 셀을 공백으로 정리하고 이미지에 alt 문구가 있으면 반영한다. 이미지 자체를 해석하거나 OCR하지 않는다.
4. 문서 상태를 확인해 정상 문서의 절만 `searchable_sections`에 넣고 FTS5 trigram 색인을 만든다.
5. Dense와 재정렬 입력에 코드·문서명·현재 절 제목/label·본문을 함께 넣는다. 상위 절 전체 경로를 추가한 비교는 이번에 하지 않았다.

원문 절 식별자인 `section_id`가 검색·Gold 단위다. 이번 실행에서 새 고정 길이 슬라이딩 청킹을 한 것은 아니다. Dense 본문 입력 1,024토큰·재정렬 쌍 1,536토큰 제한은 **모델 입력을 자르는 한도**이지, DB를 그 길이로 다시 잘랐다는 뜻이 아니다.

처리 코드: [html_text.py](../src/html_text.py), [build.py](../src/build.py). 이 두 파일과 `integrity.py`는 빌드 보고서의 builder commit `b71affc8c397e20d3ec82cc70fbb921c90bb5422` 버전과 대조해 차이가 없음을 확인했다. DB 자체는 업로드하지 않았다.

## 3. 질문 작성과 변경 이력

- 메타데이터의 작성 방식: `Codex current conversation, source-conditioned manual drafting; no external generation API`.
- 이를 “대화형 AI가 원문을 바탕으로 질문·답변 초안·필수 근거를 구성했다”고 설명할 수 있다. 특정 생성 모델 revision·고정 생성 프롬프트·temperature가 기록됐다고 말하면 안 된다. 독립적인 대량 생성 API 로그는 없다.
- 단일 근거·적용 조건·복수 근거 36문항은 이전 전체 코퍼스 v3의 질문과 Gold 그룹을 유지했다. 이전 결과에 노출된 문항이다.
- 참조 관계 12문항은 v4 결과를 보기 전에 보완·교체했다. 도구 사용 지시 대신 연결된 근거의 서로 다른 정보를 묻도록 했다. REF-12의 일반 노체 90%와 옹벽 뒤채움 95% 혼동도 고쳤다.
- [변경 이력](../experiments/evidence_response_pilot_v4/question_changes.json)과 [작성 스크립트](../experiments/evidence_response_pilot_v4/build_dataset.py)에 근거가 있다.
- 사용자 요청으로 새 사람 검수는 하지 않았다. 기존 MUL-12 확인 이력은 전체셋의 전문가 검증을 뜻하지 않는다.

과거 후보 준비 코드에는 본문 길이 70~420자, 표·이미지 없는 절, 일부 제목 제외, 과거 검토 Gold의 기준 코드 제외가 있다. 계열별 후보 문서를 해시 순서로 뽑고 그 안에서 질문을 목적에 맞게 작성했다. 참조 후보는 명시 코드와 절 번호를 파싱할 수 있는 경우에 모았다. **검색 코퍼스 전체를 사용했다는 사실과 QA 후보에 선택 조건이 있었다는 사실을 구분**해야 한다. [후보 준비 코드](../experiments/response_selection_pilot_v3/prepare_candidates.py)와 [후보 메타데이터](../experiments/response_selection_pilot_v3/authoring_pool.json)를 보관했다. v4 참조 보완의 근거는 별도 `build_dataset.py`에 명시돼 있다.

**현재 48문항은 예전 철도24+전 분야24 질문셋과 다르다.** 46문항 분모나 예전 Gold 57개를 사용하지 않는다. 모든 48문항을 이번 검색 평가에 넣었다.

## 4. Gold를 읽는 법

예를 들어 `evidence_groups = [[101, 102], [900]]`이면 첫 번째 요구는 101 또는 102 중 하나, 두 번째 요구는 900이 필요하다. 둘 다 Top-k 안에 있어야 완전 성공이다. 첫 번째 그룹만 있으면 Hit는 성공이지만 완전 성공은 아니다.

숫자는 해당 동결 DB의 절 ID다. 기준 번호·문서 페이지·검색 순위가 아니다. `answer_evidence`는 대표 절의 코드·문서명·절 제목을 제공한다. 원문 본문과 원문을 이어붙인 답변 초안은 공개용 사본에서만 제거했으며, 정답 그룹은 그대로다. v4 참조 12개의 AI 요약 초안만 답변 내용으로 남아 있다.

현재 자동 인정한 대체 근거는 같은 기준 코드와 동일한 본문을 가진 절이다. 다른 코드·다른 표현의 의미상 동등 근거를 모두 찾은 것은 아니므로 정답 누락 가능성이 남는다.
